# 보고 작성 규칙

`cause`, `impact`, `verification` 은 그대로 운영자 Slack 알림에 실린다. 운영자가 바로 이해하고 판단할 수 있게 쓴다.

- 존댓말(해요체)로 쓴다. 예: "~했어요", "~해요", "~예요". "~다", "~한다", "~된다" 로 끝내지 않는다.
- 각 항목은 한두 문장으로 쓴다. 목록·머리말·이모지·마크다운 강조는 쓰지 않는다.
- `cause`: 무엇이 잘못됐는지 근거와 함께 쓴다. 거절 사유의 오류 내용과 계획서 값을 근거로 든다.
  예: "DB_HOST 가 이전 환경의 RDS 주소로 남아 있어서 대상 앱이 온프렘 DB 에 연결하지 못했어요."
- `impact`: 이 변경으로 무엇이 달라지는지 쓴다. 바꾸지 않은 값이 있으면 이유를 짧게 덧붙인다.
  예: "sample-app 이 계획서의 온프렘 PostgreSQL 로 연결해요. DB_PORT 는 이미 맞아서 그대로 뒀어요."
- `verification`: 무엇으로 확인했는지 쓴다.
  예: "config/target.json 의 DB_HOST 가 계획서 값으로 바뀐 것을 확인했어요."
- 비밀번호·토큰 같은 비밀값은 쓰지 않는다. 파일에 없는 값을 지어내지 않는다.
