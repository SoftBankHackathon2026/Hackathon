# migration: 범위를 명시한 계정·권한 수집·계획·추가 적용 기반

## Motivation

기존 도구는 데이터베이스 이관 단계만 처리합니다. 실행 신원, 작업 권한, 대상 자원 연결과 신뢰를 분리하여 계정·권한 이관을 준비하고, 수집 누락이나 미지원 정책이 있을 때 실제 변경을 차단하는 별도 경로가 필요합니다.

## Change

`migration.identity`에 엄격한 버전 계약, 읽기 전용 수집, 두 방향의 좁은 객체 읽기 계획, 별도 SQLite 실행 기록과 잠금, 검토/원본/대상 재확인, 응답 유실 재조회·재개, 읽기 전용 복구 제안과 보고를 추가했습니다. AWS/GCP와 Keycloak/Kubernetes/OpenStack의 추가 적용기를 분리했고 실제 개발 도구 형식과 모의 통합 시험을 작성했습니다. 설치 패키지 검색·규칙 자료 포함, 선택 의존성과 별도 이미지·자동 검사를 보강했습니다.

신원 연합 자동 구성, 일반 온프레미스→클라우드 변환, 상위 정책의 완전한 수집, 격리된 쓰기/삭제 실환경 시험, 자동 복구 적용은 미완료입니다. 실제 수집 결과의 unknown 제한은 적용을 차단합니다.

## Usage

[사용·지원·복구 설명](./README.md)의 오프라인 예시를 먼저 사용합니다. 익명 예시는 실제 수집 자료가 아닙니다. `python -m migration.identity --help`에서 collect/plan/preflight/apply/resume/verify/status/rollback-plan/report를 확인할 수 있습니다.

## Impact

기존 DB 설정·상태·OPA 정책은 변경하지 않았습니다. 기존 migration/** 이미지 자동 검사도 영향을 받습니다. main 병합 뒤 기존 이미지 게시가 발생하는 설정은 유지되며 이번 작업에서는 게시·배포·원격 main 변경을 하지 않았습니다.

직접 실행 결과: 전체 Python 278개 통과·8개 건너뜀, OPA 37/37 및 정책 예시 15개 일치, 설치형 배포의 저장소 밖 설치와 규칙/양방향 계획, 전체 선택 의존성 일치, 신규·기존 DB 이미지의 로컬 빌드와 오프라인 기본 실행을 확인했습니다. 실제 계정의 접근 동등성이나 이관 완료를 검증한 결과는 아닙니다. [상세 인수 기록](./implementation-status.md)을 참고하세요.
