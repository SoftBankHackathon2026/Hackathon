## 기준 및 최종 시험

기존 기준은 코드 작성 전에 Python 3.12에서 `migration/`를 작업 디렉터리로 실행한 **94 passed, 23 skipped**입니다. 실행 제한 아래 처음 시도했을 때 로컬 임시 서버가 차단되어 실패했으며, 허용된 환경에서 재실행하여 기준을 확정했습니다. 저장소 루트 실행은 기존 `tests.conftest` import 경로 때문에 오류가 있으므로 기존 구조를 바꾸지 않고 표준 작업 위치를 사용합니다.

최종 결과는 아래 항목에 기록합니다. 실제 클라우드·Keycloak·Kubernetes·OpenStack 및 PostgreSQL 접속은 하지 않았습니다.

- Python 전체 시험: `PATH=/private/tmp/iam-tools:$PATH ../.venv/bin/python -m pytest -o addopts='' -q` (`migration/`에서 실행). 최종 수치는 아래 검증 추가 기록 참조.
- 기존 OPA 1.22.0: `opa fmt --fail -l`, `opa check --strict --ignore examples --ignore schema`, `opa test --ignore examples --ignore schema` 통과. 정책 시험 **37/37**, 저장소 `expected.json` 예시 **15개 일치**.
- AWS: 공식 botocore 요청·응답 모델 검사 2개를 포함한 전용 시험 41개 통과. 아마존 계정 호출을 모의했습니다.

## 교차 검토와 수정 근거

세 명의 서브에이전트가 AWS, GCP, 온프레미스 파일을 분리하여 구현한 뒤 서로 및 공통 코드를 읽었습니다. 리더가 변경을 직접 읽고 시험을 다시 실행했습니다.

수정한 주요 문제는 계획 내부 변경 검출, Kubernetes 기본 이름 및 실제 클러스터 서버 고정, 대상 상위 정책 문맥 재조회, 순서만 다른 API 응답의 잘못된 충돌, RoleId/uniqueId 재생성 검출, 기본 암호화만으로 개별 객체를 조사 완료로 오인하는 문제, SDK 자동 쓰기 재시도, API의 403을 권한 거부로 오인하는 문제입니다. 실제 GCP 적용기 통합 모의 시험으로 생성·연결·응답 유실·재시작·외부 변경을 다시 확인했습니다.

## 남은 개발과 필요한 실제 환경
