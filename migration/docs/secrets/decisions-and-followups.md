# 결정 이력과 후속 작업

## 발견 맥락과 사용자 결정

본 세션은 온프레미스 OpenBao 준비 PR #28의 설치·인증·단기 토큰 결과를 받아 실제 비밀값을 적재하는 Python 이관기를 요청한 작업입니다. 계정 이관 PR #51이 같은 OpenBao 경로에 읽기 권한을 구성하므로 신원·경로·정책 결과가 서로 맞아야 합니다.

사용자는 인터뷰에서 AWS Secrets Manager 우선, 구글 클라우드 후속, 현재·직전 값 이관, 실제 자격증명 교체 기능을 선택했습니다. 고객 환경마다 대상 제품이 달라지므로 특정 운영 계정·리전·목록을 개발 시 고정하지 않고 실행 입력으로 받습니다. 앱 변경은 담당 범위에서 제외하고 교체 기능과 전환 절차를 제공하며, 구현 완료 후 변경 검토 요청서에 필요한 앱 변경을 상세히 남기도록 결정했습니다.

초기 교체 제품과 값 형식은 마지막 승인에서 **PostgreSQL 일반 접속 계정, 단일 문자열과 명시적으로 지정한 JSON 비밀번호 필드**로 확정했습니다. 다른 제품은 미지원 사유와 추가 구현 필요 사항을 보고합니다.

## 키·암호화·접근 정책 구분

논의 중 '원본 정책·암호화 키를 그대로 복제하지 않는다'는 표현이 핵심 이관을 제외하는 것으로 보일 수 있어 설명을 수정했습니다. Secrets Manager에 값으로 보관한 비밀번호·서비스 호출용 키·개인키는 이관 대상입니다. 그 값을 보호하는 KMS 키 원문은 AWS에 남고, 정상 복호화 조회로 받은 같은 값을 OpenBao가 다시 암호화합니다.

업무 데이터 자체의 KMS 암호문 변환, 암호화된 데이터 키의 보호 전환, 전자서명 키 교체·신뢰 전환, 별도 보유 원본 키를 암호 연산 엔진에 등록하는 경우는 별도 설계와 승인이 필요한 확장입니다. 이번 값 이관 기능으로 지원했다고 표시하지 않습니다.

권한은 정책 이름을 복사해서 부여할 수 없습니다. 원본 주체·자원·작업·조건과 대상 신원·경로 연결이 필요합니다. 계정 도구는 읽기 경로와 인증·정책을 소유하고 본 도구는 근거를 보관하고 연결을 대조합니다. 값 복사와 별개로 실제 허용·거부 시험이 필요하며 미실행을 완료로 표시하지 않습니다.

## 향후 권한 확장을 위한 선행 준비 세 가지

사용자는 사이드 대화에서 다음 세 항목만 이번 계획의 추가 요구사항으로 채택했습니다.

1. **원본 정책 근거:** 정책 원문·주체·자원·조건·조사 시점과 수집 출처를 보관합니다. 정책 이름만으로 대체하지 않습니다.
2. **확장 가능한 대응표:** 조회·생성·수정·삭제·복원·영구 파기·관리 작업을 구분합니다. 미지원 작업은 유보 상태이며 자동 권한 부여가 아닙니다.
3. **안정된 신원·경로 연결:** 원본 계정·리전·주체·비밀 고유 식별자와 대상 신원·경로를 연결하여 같은 이름의 새 객체를 채택하지 않습니다.

추가 제안이었던 운영 쓰기 활성화 경계, 운영 수정 이후의 검증 체계, 향후 권한·데이터 복구 범위 구분은 새로운 요구사항으로 채택하지 않았습니다. 이 결정이 기존 복사·검증·재개·교체 실패 대응 요구사항을 없애는 것은 아닙니다. 실제 쓰기·삭제·관리 권한 자동 적용 기능은 추가하지 않았습니다.

## 계정 PR과 준비 도구의 영향

- 계정 PR #51의 `52205b5026c9a5a46f64ddab2501bb474c820f57`을 읽기 전용 참고로 고정했습니다. 기존 브랜치는 변경하지 않습니다. 그 코드가 직접 생성한 계획을 새 도구가 소비하는 호환 검사를 제공합니다.
- 최신 main에 병합된 OpenBao 준비 모듈을 사용합니다. 준비 결과의 전역 `ready` 문구와 실제 서비스·이관 검사를 구분하고, 나머지 미완료 상태를 보존합니다.
- 준비 토큰의 권한을 늘리는 대신 한 경로의 전용 문서에 두 버전과 참조를 보관합니다. 범용 KV 읽기 코드를 그대로 쓰는 앱에는 조회 규약 반영이 필요합니다.
- 원본 정책·조사 결과와 계획은 민감한 운영 자료입니다. 공개 저장소에는 가상 예제만 포함합니다. 파일 요약값은 승인자의 신원이나 전자서명을 증명하지 않습니다.
- 계정 대응이 없는 고객 환경의 값 복사를 인력용 Identity Center 계획에 강제로 종속시키지 않습니다. 권한 연결 유보를 명시한 경우에만 값 적재를 허용하고 소비자 신원·정책·접근 검증은 미완료로 남깁니다. 이는 일반 프로그램 신원의 자동 변환이나 새 권한 부여를 추가한 것이 아닙니다.

| 과제 | 추가 입력·구현 | 인수 기준 |
|---|---|---|
| 앱 조회·전환 | 제품·배포 방식, 인증서·서비스 계정 토큰 전달, 전용 문서의 현재 값 해석, 비밀 갱신·연결 풀 처리 | 실제 앱이 새 값으로 업무를 수행하고 범위 밖 조회가 거부됨. 재시작·실패 복구 결과 확보 |
| MySQL·서비스 호출용 키 | 대상 제품·버전·관리 신원, 중복 키 허용 기간, 재발급·회수 기능 | 같은 후보로 재개 가능하고 실제 접속·거부·회수 확인 |
| 쓰기·삭제·관리 권한 | 보관한 원본 근거, 목적지의 생성·수정·버전 삭제·복원·파기·관리 의미 | 제한·조건 보존, 허용·거부 및 권한 확대 방지 시험. 새 명시 승인 후 구현 |
| 복잡한 정책 | 조직·세션·자원·키 제한·위임과 실제 사용 의도 | 실효 권한과 차이 분석 및 제한 보존. 현재의 검토 근거를 자동 등가 평가로 대체하지 않음 |
| 데이터 암호화·서명 서비스 | 데이터 형식·알고리즘·키 보유 여부·기존 검증자·대상 연산 엔진 | 암호문 변환·복호화 또는 과거/신규 서명 검증과 실제 앱 전환 시험 |
| 구글 클라우드 | 조직·프로젝트·실행 신원·비밀 버전·대상 정책 | 별도 수집·현재/직전 선택·원본 검증과 제한 보존 |
| 실환경 운영 인수 | 승인된 시험 AWS 계정, 실제 온프레미스 인증·네트워크·키 인계·백업 복구, 대상 PostgreSQL과 앱 | 실제 제품 조합·사용자·업무·재개·복구 결과. 로컬 시험을 운영 이관 완료로 해석하지 않음 |

용어: PR은 변경 검토 요청, KMS는 키 관리 서비스, KV는 키·값 저장 기능, JSON은 이름·값 자료 형식입니다.
