기본 전체 검사에서 기존 외부 PostgreSQL 접속 정보·정책 검사 도구가 필요한 시험은 건너뜁니다. 실제 indexer 시험도 명시적인 시험 주소가 없으면 건너뛰며 별도 실행 결과를 위 표에 기록합니다. 모의 시험·문법 검사로 Ubuntu 설치 성공을 주장하지 않습니다.

실제 indexer 시험 이미지는 `wazuh/wazuh-indexer:4.14.10`, 검증한 이미지 요약값은 `sha256:e56f85ed9e79f113c0f2d2a7965171cd8e063262ec88e110086acdb1f69f2240`입니다. 로컬 루프백 주소에만 공개하고 보안 플러그인을 끈 **시험 전용** 구성입니다. 이 시험은 실제 설치의 암호화·역할 설정·Wazuh 전체 경로를 검증한 것이 아닙니다. 설치 코드는 보안 플러그인을 활성화하고 인증서를 사용합니다.

## 재현 명령

저장소의 `migration/`에서 실행합니다.

```sh
python -m pip install '.[wazuh-infra,dev]' build wheel 'setuptools>=69' ruff==0.17.4
ruff check --isolated --select E9,F,I migration/wazuh_infra tests/wazuh_infra
ruff format --check migration/wazuh_infra tests/wazuh_infra
python -m pytest -ra
python -m build --no-isolation
```

실제 indexer의 시험 전용 컨테이너를 준비한 경우에만 다음 명령을 실행합니다. 검사는 루프백 주소의 암호화하지 않은 시험 서버만 허용하며 기존 운영 주소를 입력하지 않습니다. 자동 검사 구성인 `.github/workflows/wazuh-infra.yml`에 컨테이너의 시작·준비 확인·정리 절차를 포함했습니다.

```sh
WAZUH_TEST_INDEXER_URL=http://127.0.0.1:19200 \
  python -m pytest tests/wazuh_infra/test_indexer_live.py -ra
```

## 아직 수행하지 않은 인수 검증

- 실제 Kubernetes 노드에서 machine-id·하드웨어 식별값·원격 접속 주소의 일치 및 권한 부족·접속 단절 처리
- Ubuntu 24.04 신규 패키지 설치·부분 설치 재개·재시작·재부팅 후 데이터와 인증서 보존
- 실제 Wazuh manager·Filebeat·indexer·dashboard 전체 연결과 운영자·조회자의 실제 화면 권한
- `verification.probe: true`의 실제 manager 입력부터 archives 검색까지의 경보 없는 이벤트 전달
- 실제 AWS S3·CloudWatch 접근·암호 해독·과거 로그 범위·수집 처리 기록·단기 자격증명 갱신
- 디스크 부족·마운트 변경·서비스 중단·인증 만료 상황에서 실제 저장공간 감시와 입력 정지
- 별도 원본 이관 도구 연결·원본 다운로드·대량 이관·전체 이벤트 수 대조·격리 백업 복원

설치·검색 기반의 준비 상태와 실제 원본 이관 완료는 다른 결과입니다. 실제 전체 범위 대조를 수행하지 않았으므로 `full_migration_verified`는 항상 거짓입니다. 이번 결과물을 운영 환경에 적용하기 전 위 항목을 시험 노드에서 확인해야 합니다.

용어: HTTPS는 인증서를 사용하는 암호화 웹 통신, JSON은 구조화된 데이터 형식, SHA-256은 파일·이미지 무결성 확인에 쓰는 요약값 계산 방식, wheel은 설치 가능한 Python 배포 패키지입니다.
