# 관리자 승인 설치 검사

2026-11-07, Ubuntu 24.04의 ARM64와 AMD64 시험 이미지에서 설치 기능을 확인했습니다. AMD64는 ARM Mac의 Docker 아키텍처 에뮬레이션으로 실행했습니다. 실제 원격 고객 호스트에 패키지를 설치한 결과는 아닙니다.

## 사용자 흐름

1. 웹에서 새로 복사한 명령을 일반 사용자로 실행합니다.
2. 검증된 실행 파일이 단말 증명을 제출하고 확인 코드를 표시합니다.
3. 웹에서 확인 코드를 입력해 단말을 승인합니다.
4. 보조 프로그램·정책·필수 네트워크 도구가 준비되지 않았다면 터미널에 패키지 이름, 설치 경로, 실제 사용자, 연결 상대와 제한된 관리자 실행 권한을 표시합니다.
5. `[y/N]`에 동의하면 `sudo`가 관리자 인증을 직접 받습니다. 연결 프로그램은 비밀번호를 읽거나 저장하지 않습니다.
6. 누락된 Ubuntu 패키지와 이중서명 목록에 포함된 보조 프로그램·정책을 설치합니다.
7. 단말 승인 상태를 다시 확인한 뒤 같은 등록 요청으로 터널 연결을 계속합니다. 설치 중 철회됐다면 터널을 열지 않습니다. 이미 승인하여 설치한 패키지는 유지됩니다.

설치 거절·실패 시 터미널에 같은 요청을 이어가는 `resume` 명령을 안내합니다. 초대 증명 60초와 웹 승인 대기 5분은 연장하지 않았습니다. 긴 관리자 입력·패키지 설치는 웹 승인 완료 후에 실행합니다. 정상적으로 사전 설치된 단말은 설치 승인을 생략합니다.

## 실행 결과

| 검사 | ARM64 | AMD64 |
| --- | --- | --- |
| 실제 OpenSSL 암호·TLS·배포 검증 및 설치 검증 함수 | 17개 통과 | 17개 통과 |
| 변조된 보조 프로그램 거절, 시스템 무변경 | 통과 | 통과 |
| 대화형 터미널이 없는 경우 거절, 시스템 무변경 | 통과 | 통과 |
| 설치 동의 거절, 시스템 무변경 | 통과 | 통과 |
| 실제 `sudo` 비밀번호 인증, 실제 Ubuntu 저장소에서 3개 패키지 설치 | 통과 | 통과 |
| 보조 프로그램·정책·제한된 권한 규칙의 소유자·권한, 추가 인수 실행 거절 | 통과 | 통과 |
| 시험용 광범위 관리자 권한 제거 후 비대화형 재실행 | 통과 | 통과 |
| 기존 관리자 정책 충돌 시 설치 거절, 시스템 무변경 | 통과 | 통과 |
| 실제 K3s 방식 `/usr/local/bin/kubectl` 탐색, 보조 프로그램 부재 시 초기 실행 진행 | 통과 | 통과 |
| kubectl 부재 시 정확한 도구 이름 안내 | 통과 | 통과 |

실제 설치 도구는 아키텍처마다 6개 시나리오를 검사하고 초기 실행 도구는 2개 조건을 검사합니다. 네트워크 도구 3개를 실제로 제거한 새 임시 컨테이너에서 인증과 재설치를 수행했습니다. 패키지 설치 성공을 모의 명령으로 대신하지 않았습니다. 시험용 비밀번호와 원문 터미널 기록은 출력하지 않으며 시험 컨테이너는 삭제했습니다.

Python의 연결 제어/API·배포 도구 시험 58개와 하위 검사 12개도 통과했습니다. macOS에서 로컬 통신용 포트 생성을 제한한 실행은 통과로 세지 않았으며, 권한을 갖춘 재실행에서 암호 통신 시험을 통과했습니다.

시험 배포 `live-e2e-5`에 두 아키텍처의 새 묶음을 적용했습니다. 양쪽 Ubuntu 컨테이너에서 실제 게시 주소의 HTTPS 인증서·초기 해시·이중서명·다운로드한 실행 파일을 확인했고, 웹 기능 조회가 `available: true`와 새 배포 버전을 제공하는 것도 확인했습니다. 기존 공개 포트와 데이터는 보존했습니다.

## 배포 환경과 검증 경계

연결 상대와 터널 주소·포트는 배포자가 지정하는 `--client-net-policy` 파일에서 읽습니다. `role: "client"`, `uid: 0`의 서명 정책을 현재 사용자 번호로 바인딩합니다. 보조 프로그램과 정책은 함께 이중서명해야 합니다. 고객 정보·인증값·시험 IP를 제품 코드에 고정하지 않습니다. 기존 관리자 정책과 다르면 자동으로 덮어쓰지 않습니다.

이번 설치 시험은 새 설치 경로의 실제 인증·패키지·파일 권한 검사입니다. 이번 변경으로 **실제 원격 단말에서 웹 복사부터 터널·수집·등록까지 같은 요청으로 다시 통과한 것은 아닙니다.** 이전 전체 흐름 검사는 [기존 실제 연결 기록](live-acceptance.md)에 별도로 보존합니다. 원격 호스트에서는 관리자가 새 명령으로 직접 승인한 후 연결 결과를 확인해야 합니다.
