# 디자인 시스템

Oneport 는 인프라 환경을 옮기고 지켜보는 콘솔이다. 구조, 밀도, 상호작용은 Datadog(DRUIDS, Fleet Automation,
Data Jobs Monitoring, Cloud Security)을, 면과 회색은 토스 TDS(라이트)를 따른다.

- 토큰: `frontend/src/styles/tokens.css`
- 역할 규칙: `frontend/src/styles/system.css`(마지막에 불러와서 같은 역할을 같은 모양으로 고정)
- 컴포넌트: `frontend/src/components/`

새 화면은 아래 컴포넌트만으로 만든다. 화면 전용 클래스로 글자 크기, 표 모양을 다시 정하지 않는다.

## 화면 뼈대

| 자리 | 컴포넌트 | 규칙 |
|---|---|---|
| 위쪽 고정 막대 | `AppShell` + `PageActions` | 왼쪽 현재 위치(상위 / 현재), 오른쪽 기간 선택, `RefreshStatus`, 계정. 제목을 두지 않는다 |
| 화면 머리 | `PageHeader` | 제목 24 + 상태 + 오른쪽 주요 동작 하나, 한 줄 설명(선택), 탭. 상세 화면은 `crumb` 로 상위 화면을 건다 |
| 필터 줄 | `ScopeFilterRow` + `FilterSelect` | 화면 전체 범위를 바꾸는 선택 상자. 화살표는 상자 안 오른쪽 |
| 먼저 볼 것 | `StatTiles` / `AttentionStrip` | 첫 화면에서 판단이 필요한 화면에만(마이그레이션, 작업 상세). 환경처럼 그림이 주인공인 화면에는 두지 않는다 |
| 대시보드 위젯 | `Widget` | 여러 판단을 한 화면에 모으는 개요 탭 전용(보안 개요, 비용 개요). 흰 면 + 머리(제목 14, 보조 줄, 글자 링크 하나) + 구분선. 12칸 격자에 2~3개씩. 위젯을 누르면 해당 목록 탭으로 이동, 필터 |
| 필터 타일 | `FilterTiles` | 목록이 주인공인 화면(보안)의 위쪽 한 줄. 묶음별 작은 타일(숫자 + 라벨), 누르면 아래 목록이 걸러지고 다시 누르면 풀린다(Datadog Security Inbox) |
| 섹션 | `Section`, 상세 화면은 `DashSection`(같은 모양) | 흰 면, 제목 18 + 개수/상태 + 글자 링크 하나 |
| 환경 연결 | `PreparePage` (마이그레이션 준비, `features/prepare/`) | 두 단계 등록 흐름(환경정보 수집 → 환경 등록). 위에 큰 단계(환경 연결, 앱 선택), 왼쪽 흰 카드에 연결 환경 목록, 오른쪽 흰 카드에 지금 단계(안쪽 단계 표시, 단계 화면, 연결 관리, 수집/등록 기록). 화면 머리는 제목만(상위 경로는 위쪽 막대). 연결 서비스를 쓸 수 없으면 위에 주의 칸 안내. 단계 화면은 `?connection-preview=1#prepare` 미리보기로 확인. 스타일은 `prepare.css`(글자 토큰) |
| 리소스 트리 | `ResourceTree` (환경 계층 보기) | Argo CD 방식 가로 트리: 환경 → VPC, 서브넷, 클러스터 → 네임스페이스 → 구성 요소. 노드 = 아이콘 + 이름 + 종류, 오른쪽 상태 점(문제일 때만 글자). 문제 없는 네임스페이스는 접어 두고, 구성 요소를 누르면 오른쪽 상세 패널 |
| 오른쪽 상세 패널 | `SidePanel` + `PanelGroup` | 목록에서 행을 누르면 연다. ↑↓ 이전, 다음, Esc 닫기, 다른 행을 누르면 내용만 바뀜 |

## 개요 화면을 만드는 순서

Datadog Fleet Automation, Data Jobs 의 개요처럼 위에서 아래로 "무엇을 봐야 하나 → 어떻게 돌아가나 → 목록" 순서.

1. **먼저 볼 것**(타일 줄): 숫자 + 무엇의 개수 + 근거 한 줄. 0 이면 흐리게, 문제가 있으면 숫자 색과 라벨 앞 점. 누르면 해당 목록으로 이동, 필터.
2. **흐름**(마이그레이션, Wiz 노출 관리 개요 방식): 한 패널을 6단계 열로 나누고, 열마다 단계 이름, 지금 있는 작업 수(큰 숫자)를 둔다. 숫자 아래 흐름 띠는 단계까지 온 작업 수만큼 두껍다(단색). 그 아래 하는 일 한 줄, 단계 지표, 작업 칩.
3. **목록**: 정렬되는 표 + 오른쪽 패널.

## 환경 다이어그램(인프라 경계)

Cloudcraft(Datadog) 방식. 3D 인프라 경계 보기와 계층 트리에 같은 규칙을 쓴다.

- **경계 단계 색**(`LEVEL_COLORS`, `blockStyle.ts`): 계정/사이트 회색, 리전 보라 점선, VPC 초록, 서브넷 파랑, 클러스터 주황, 네임스페이스 회색 점선. 경계선, 경계 이름, 캔버스 왼쪽 위 단계 범례(`BoundaryKey`), 패널의 배치 트리가 같은 색을 쓴다. 다른 뜻으로 이 색을 쓰지 않는다.
- **글자**: 경계 이름은 화면에서 12px, 환경 이름은 16px 이상(바닥면을 따라 기울여 씀). 블록 이름은 "● 이름"(상태 점 + 13px 굵게).
- **이름 배치**: 블록 아래 긴 이름 → 보통 이름(아래, 오른쪽, 왼쪽, 위) → 짧은 이름. 경계 이름과 문제 표식을 먼저 피하고, 자리가 없으면 확대했을 때 보인다. 문제 표식(번호 + 이름)이 있는 블록은 이름표를 따로 달지 않는다.
- **캔버스 높이**: 너비에 맞춰 그렸을 때 높이(최소 480px, 화면 높이의 70% 이하).
- **파드**(`podModel.ts`): Cloudcraft 처럼 기본은 숨기고 툴바 "파드 보기"로 켠다. 켜면 워크로드 블록 오른쪽에 파드 하나 = 작은 블록(5칸씩 최대 3줄, 상태색: 정상 초록, 시작 중/준비 안 됨 주황, 실패/재시작 반복 빨강, 완료/정보 없음 회색, 문제 파드 먼저, 넘치면 +n). 블록 이름 뒤 "준비/전체"(파드 2개 이상이거나 모자랄 때만, 모자라면 빨강). 패널 "파드" 섹션은 칸 + 준비 수 + 재시작 합, 파드별 이름, 상태, 노드, 시작 후, 컨테이너 준비 수. 사유는 "재시작 반복(CrashLoopBackOff)"처럼 한국어 + 원문. 파드 목록(`EnvComponent.pods`)이 없으면 detail 의 준비 수로 칸 수만 그린다.
- **접속 주소**(`endpointModel.ts`, `EnvComponent.endpoints`): 패널 머리에 채움 버튼 "열기"(새 탭) 하나, 본문 맨 위 "접속 주소"에 주소 + 복사, 아래 줄에 용도, 출처(인그레스 / 로드 밸런서 / 노드 포트 / 클러스터 내부), 공개 범위(공개 / 내부망). 공개인데 HTTP 면 "암호화 안 됨(HTTP)". 순서는 공개 → 내부망, HTTPS → HTTP, 인그레스 → 로드 밸런서 → 노드 포트 → 클러스터 내부. http(s) 만 링크로 열고 클러스터 내부 주소는 복사만. 구성 요소 표 "접속" 열, 다이어그램 이름 뒤 ↗. 문서와 캡처에는 실제 주소 대신 예시 주소(192.0.2.x, example.com)를 쓴다.
- **노드 보기**(`NodeCanvas.tsx`, `nodeLayout.ts`, `clusterModel.ts`, `FleetEnvironment.cluster`): 툴바 "그룹 기준"의 "노드". Cloudcraft 쿠버네티스 그림처럼 클러스터 판(주황) → 영역 판(보라 점선, 영역마다 세로 열) → 노드 판(흰 상자) → 파드 블록. 노드 판 윗면에 "● 노드 이름"과 CPU/메모리 막대(실측, 없으면 요청량을 옅게. 실측이 있으면 요청량은 눈금). 한 클러스터의 노드 판은 크기를 같게 해서 나란히 비교한다. 파드는 구성 요소별로 이웃하게 놓고 상태색, 구성 요소에 속하지 않은 파드(시스템 파드)는 연회색. 파드에 올리면 이름/구성 요소/상태/재시작/노드 카드가 뜨고, 같은 구성 요소 파드가 모든 노드에서 같이 강조된다(워크로드가 어느 노드에 퍼져 있는지). 파드를 누르면 구성 요소 패널, 노드 판을 누르면 노드 패널, 클러스터 판을 누르면 클러스터 패널. 환경은 캔버스에 가장 크게 들어가는 열 수로 격자 배치(iso 대각선 계단 방지). 주소 `#environments/nodes/<환경>/<노드>`. 노드 이름은 도메인을 떼고, 관리형 노드 풀처럼 길면 끝 해시만(…232bdfd8-dkj8).
- **클러스터/노드 패널**(`ClusterPanel.tsx`): 클러스터는 자원(CPU/메모리: 할당 가능 막대 위에 요청 옅게, 실사용 진하게, 비율은 실사용 기준이고 없으면 "요청" 표시) → 노드 표(상태, CPU/메모리 미니 막대, 파드 수, 누르면 노드 패널) → 배치 대기 파드. 노드는 자원 → 파드(구성 요소별 묶음, 문제 있는 묶음 먼저, 나머지 시스템 파드 수) → 정보(이름, 역할, 새 파드 배치(cordon), kubelet, OS). ↑↓ 로 노드 이동. 붐빔 색은 75% 이상 주황, 90% 이상 빨강. null 은 "모름"/"못 읽음"으로 쓰고 0 과 구분한다. 왼쪽 환경 요약에 "클러스터 노드 n/m 준비"(누르면 클러스터 패널)와 "사용률"(실측이 없으면 "요청률").
- **구성 요소 패널**(`ComponentPanel`, `SidePanel` 위): 머리 = 이름 + 상태, 환경 / 계층 / 운영. 본문 = 배치(단계 색 트리), 상태(준비 막대, 워크로드 수, 메모), 연결(쓰는 구성 요소 / 이 구성 요소를 쓰는 곳, 누르면 그 구성 요소로), 이전 작업(원본 DB, 대상 DB, 이전 도구, 환경 간 연결), 보안(실패한 통제, 심각도 막대), 월 비용(관리형 서비스는 비용 항목과 연결, 클러스터 워크로드는 "클러스터 노드 비용에 포함"). 다이어그램, 계층 트리, 구성 요소 표가 같은 패널을 쓴다.

## 비용 화면

AWS Billing 홈, Datadog 비용 요약, Infracost PR 댓글을 참고한다. 탭은 개요 / 이전 영향 / 환경별(주소 `#costs/migration` 처럼 바로 열 수 있음).

- **개요 위젯**: 월 비용 합계(큰 숫자 + 클라우드/온프렘 + 환경별 비중 막대와 범례), 분류별 월 비용(환경마다 누적 막대, 길이 = 월 비용), 이전 작업별 월 비용 변화(지금 / 이전 후 / 월 변화 / 일회성 비용 / 대상 클러스터, 행을 누르면 이전 영향 탭), 월 비용이 큰 자원, 계산 기준과 빠진 항목.
- **비교표**(Infracost 방식): 환경 / 지금 월 비용 / 변화 / 이전 후 월 비용, 맨 아래 합계와 %. 표 옆에 일회성 비용과 대상 클러스터 수용 가능 여부.
- **자원별 변화**: 지금(원본) / 이전 후(대상) / 변화 종류 글자(관리형으로 전환, 그대로 옮김, 새로 생김, 원본에서 없어짐) / 분류 / 월 변화. 기호(~ → + −)만으로 뜻을 전하지 않는다.
- **분류 색**: 컴퓨트, 메시징, 데이터베이스, 스토리지, 네트워크는 차트 범주색, 컨트롤 플레인과 데이터 전송은 회색. 위젯, 표의 분류 칸, 환경별 막대에서 같은 색을 쓴다.
- **장비비가 없는 온프렘**: 같은 사양 AWS 가격으로 환산하고 "AWS 가격으로 환산"이라고 적는다. 이전 뒤에도 장비 비용은 그대로이므로 지금과 이전 후에 같은 값을 쓴다.

## 요소

- **상태**: 점 + 1~2단어(`StatusLabel`). 배경을 채운 알약은 쓰지 않는다.
- **심각도**: 작은 단단한 태그(`sev-tag`). 치명, 높음은 채움, 중간, 낮음은 옅은 면. 여러 개는 `SeverityCounts`("높음 3, 중간 1").
- **점수**: 목록의 한 열 또는 막대 목록(`EnvScores`)으로, 가장 낮은 것부터. 판정색은 점수 글자와 막대에만, 카드 배경을 칠하지 않는다.
- **규칙 행**: 분류 아이콘 타일(`CategoryIcon`, 분류마다 옅은 면) + 제목(13 굵게) + 보조 줄(ID, 분류, 12 회색).
- **심각도 막대 표식**: `SeverityMeter` — 네 칸 중 심각도만큼 채움 + 글자. 목록에서는 태그 대신 이것을 쓴다(태그는 패널 제목에만).
- **결과 수, 준수율**: `● 통과 n ● 실패 n` + 얇은 준수 막대와 %(낮을수록 빨강).
- **영향 경로**: `ImpactPath` — 인터넷 → 진입점 → 워크로드 → 데이터 열, 노드 색은 3D 블록과 같은 종류색(`kindColor`), 문제 리소스엔 빨간 점.
- **표**(`pk-table` 하나):
  - 머리 36px(12 회색), 행 40px(13), 줄무늬 없음, 옅은 가로선. 1열 이름, 2열 상태, 숫자는 오른쪽 정렬 + tabular, 빈 값 "-".
  - 정렬: `useSort` — 머리를 누르면 내림차순 → 오름차순 → 원래 순서. 값 없는 행은 늘 아래.
  - 긴 목록은 `sticky` 로 머리 고정.
  - 합계: 표 위 오른쪽에 `pk-total`(라벨 + 18 굵은 숫자), 맨 아래 `tfoot` 은 옅은 띠 + 굵은 글자. 합계를 맨 아래에만 두지 않는다.
  - 행을 누르면 `SidePanel`, 이름 링크는 상세 화면.
- **타일**(`StatTiles`): 라벨(문제면 앞에 점) → 큰 숫자(+단위) → 막대(선택) → 근거. 회색 바탕 위에서는 흰 면, 흰 섹션 안에서는 옅은 면 + 선.
- **진행**: 작업 진행 화살표(`PhaseChevrons`, 이전 흐름 6묶음, 지난 칸 초록, 지금 칸 상태색) + 지금 묶음 이름. 비율은 `ratio-cell`(얇은 막대 + %).
- **키값**: 가로(`kv-inline`, 라벨 위 / 값 아래), 패널 안은 `PanelGroup`(왼쪽 라벨 + 오른쪽 내용).
- **버튼**: `pk-button`(채움, 화면당 하나) / `pk-button weak`(회색 면). 세그먼트는 같은 내용의 보기 전환에 3개까지.
- **그래프**: 그라데이션 없음, 0부터, 8계열까지. 이전 전후는 변화 그래프(전 → 후 점), 비중은 정렬된 가로 막대, 토폴로지는 3D 기본.
- **로딩**은 스켈레톤, **빈 상태**는 다음 행동을 알려 준다.
- **가장자리 색 띠 금지**: 카드, 행, 안내 상자의 한쪽 가장자리에만 색 띠를 두지 않는다. 상태는 숫자 색과 라벨 앞 점으로, 선택된 행은 옅은 배경으로만 표시한다.

## 문구

해요체, 능동형. 반복 부제, 로딩 안내, "~를 보여 줘요"를 쓰지 않는다. 결론 한 문장 헤드라인은 쓰지 않는다.

- **구분 기호**: 가운뎃점(·)은 쓰지 않는다. 나열은 ", ", 짝을 이루는 말은 "/"(예: ID/접근, 탐지/감사, 출발/도착), 위치 경로는 " › ".
- **명확하게**: 무엇이 어떤 상태인지 드러나게 쓴다. "문제", "이상", "남음", "남는 용량", "몫", "증가분/감소분"처럼 뜻이 흐린 말을 쓰지 않는다.
- **짧게**: 라벨과 상태는 명사형으로 짧게(예: 비정상 앱, 중단된 작업, 대상 클러스터 수용 가능 여부, 여유 자원). "~이 아닌", "~되었거나 ~한" 같은 긴 문장형 라벨을 쓰지 않는다. 괄호를 겹치지 않는다(예: "대상: AWS EKS oneaction (서울)").
- **상태 이름(앱, Argo CD)**: 정상 / 실행 오류(Degraded) / 배포 안 됨(Missing) / 저장소 설정과 다름(OutOfSync) / 배포 중(Progressing) / 상태 정보 없음(Unknown).
- **상태 이름(구성 요소)**: 정상 / 일부 파드만 준비됨 / 중단 / 복제본 0개 / 상태 정보 없음.
- **보안**: 실패 / 통과 / 미확인. 목록 이름은 "발견 사항", 항목은 "통제", 점수를 낼 수 없으면 "점검 결과 부족".
- **비용**: 일회성 비용, 가격 정보 없음, 지금 월 비용, 이전 후 월 비용, 월 변화. 표 맨 아래 제외 항목은 "(가격 정보 없는 n개 제외)".
- **링크**는 결과를 말한다(예: 실패 통제 보기, 환경 보기). **오류**는 원인 + 해결 방법 + 버튼.
