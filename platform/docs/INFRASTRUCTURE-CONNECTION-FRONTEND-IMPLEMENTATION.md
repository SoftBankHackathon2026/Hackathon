# 환경 연결 화면 구현 및 로컬 확인

작성일: 2026-11-06
대상: PR #14, `feat/platform-prepare`
구현 기준: [화면 구현 계획](INFRASTRUCTURE-CONNECTION-FRONTEND-PLAN.md)

## 구현 상태

**환경 선택·단말 확인·터널 진행·계획 검토·작업 결과·연결 관리의 화면과 상호작용을 구현했습니다. 실제 등록 서버·단말·게이트웨이 연결은 미구현입니다.**

기존 SSH 개인키·비밀번호·kubeconfig 입력과 전달 토큰 기반 명령을 준비 화면에서 제거했습니다. AWS·GCP·온프레미스는 같은 단계 흐름을 사용합니다. 서버 지원이 없는 실제 화면은 명령 발급·승인·고객 변경을 허용하지 않습니다. 서버 초안과 스크립트는 이번 프런트엔드 변경에서 수정하지 않았습니다.

## 로컬에서 확인

화면 캡처: [환경 선택](assets/connection-frontend/environment-selection.png), [계획 검토](assets/connection-frontend/plan-review.png), [모바일 계획 검토](assets/connection-frontend/plan-review-mobile.png). 모두 실제 고객 자원이 없는 개발 미리보기입니다.

Node.js 24 계열과 npm을 사용하는 현재 개발 환경에서 확인했습니다.

```bash
cd ~/workspace/competition/2026-softbank/1_main/dev/platform/frontend
npm ci
npm run dev:connections
```

브라우저에서 [로컬 미리보기](http://127.0.0.1:4320/?connection-preview=1#prepare)를 엽니다. 이미 4320 포트에 개발 서버가 실행 중이면 새로 실행하지 않고 이 주소를 여세요. 서버는 루프백 주소에만 바인딩합니다.

1. 프로젝트와 환경 이름을 입력합니다. AWS·Google Cloud·온프레미스와 출발/도착 역할을 선택할 수 있습니다.
2. `실행 준비 확인`을 누르고 준비 항목을 확인합니다.
3. `미리보기 명령 복사`를 누릅니다. **클립보드에는 실행 불가능한 설명 주석만 복사하며 등록 비밀·실제 명령을 넣지 않습니다.**
4. 아래 `미리보기 조작`에서 `단말 실행 재현`을 누릅니다.
5. 코드 `ABCD 2345`를 입력하고 직접 실행한 단말임을 확인한 뒤 승인합니다. 틀린 코드를 입력하면 남은 횟수가 줄어들고, 5회 실패 시 후보가 종료됩니다.
6. `터널 확인 재현`을 누릅니다. 온프레미스는 Kubernetes 문맥을 직접 선택하고 `대상 확인 후 계획 받기`를 누릅니다.
7. 대상·권한·변경·작업 정의·계획 해시를 검토한 뒤 체크박스와 `이 계획 승인`을 사용합니다.
8. `작업 검증 재현`으로 준비 완료 결과를 확인합니다. 앱 선택은 아직 구현되지 않아 다음 버튼은 비활성입니다.
9. `연결 해제`와 확인 버튼으로 서버 차단·터널 차단·고객 권한·단말 정리가 분리되는지 확인합니다.

`다른 상태 살펴보기`에서는 등록 만료, 인증 제한, 키 교체, 연결 장애, 부분 실패, 결과 불명, 해제 후 정리 미확인을 바로 열 수 있습니다. 선택한 환경과 예시 상태는 이 탭의 세션 저장소에만 보관되며 새로고침 후 요청별 주소로 복원합니다. 등록 생성값·개인키·공개키 원문은 저장하지 않습니다.

예시 AWS 계정은 `111122223333`, GCP 프로젝트는 `oneport-demo-project`입니다. 예상 식별자를 입력했다면 예시 값과 다를 때 대상 확인을 거절합니다. 실제 고객 자원 검증 결과가 아닙니다.

## 운영 화면과 개발 전용 미리보기

| 구분 | 동작 |
| --- | --- |
| `/#prepare` | 기존 로그인/플랫폼 경로를 유지합니다. 새 연결 서비스 준비 중 사유를 표시하고 명령 발급을 차단합니다. |
| 개발 서버의 `?connection-preview=1#prepare` | 서버 없이 화면을 검토하는 명시적 미리보기입니다. 로그인 우회는 이 개발 진입점에서만 적용됩니다. |
| 배포 빌드 | `import.meta.env.DEV` 분기가 제거되어 미리보기 앱·상태 조작기·예시 코드는 포함되지 않습니다. 주소에 미리보기 인자를 넣어도 기존 앱이 실행됩니다. |

프로덕션 호출을 위한 가상의 읽기·취소 경로를 만들지 않았으며 기존 `/api/v1/enrollments` 또는 스크립트로 자동 전환하지 않습니다. `ConnectionGateway`는 **화면용 제안 계약**이며 서버에서 구현됐다는 선언이 아닙니다.

## 구현한 보호와 검증 경계

- 등록·단말·터널·계획·작업 상태를 분리합니다. 터널만 연결되었다고 작업이나 이관 성공을 표시하지 않습니다.
- 브라우저 난수 32바이트에서 ML-DSA-65 공개키를 만들고 확장 개인키를 즉시 덮어씁니다. 생성값은 복사 처리 함수 안에서만 사용하고 최종적으로 덮어씁니다. 자바스크립트의 완전한 메모리 소거를 보장하지 않습니다.
- 클립보드 쓰기를 사용자 클릭 안에서 시작하고 비동기 준비 결과를 제공합니다. 복사 거부 시 미사용 요청 취소를 시도하며, 취소가 확인되지 않으면 성공이나 취소 완료로 표시하지 않습니다.
- 개발용 클립보드 내용은 비밀 없는 주석입니다. 운영 명령 생성 함수는 별도로 주소·요청 식별자·길이를 검사하지만, 배포 주소와 서버 계약이 없어 실제 화면에서 호출하지 않습니다.
- 타이머는 서버 시각 표본과 단조 증가 시계를 사용합니다. 만료·횟수·권한·대상·해시가 맞지 않으면 승인할 수 없습니다.
- 상태 신선도가 확인되지 않으면 승인 행동을 막습니다. 키 교체·부분 실패·결과 불명·해제 후 정리 미확인을 별도로 표시합니다.
- 조직별 승인 권한은 실제 서버에서 받아야 합니다. 현재 데모 역할을 실제 권한으로 승격하지 않습니다.
- 원본 G0의 브라우저/OpenSSL 교차 검증, 실제 양자내성 연결, 원본 A01~A18의 실환경 보안 시험은 수행하지 않았습니다. 브라우저 내부 키 재현 시험과 구분합니다.

## 파일과 의존성

준비 화면은 `platform/frontend/src/features/prepare/`의 대상 입력·단계 화면·상태 모델·복사 처리·암호 모듈·개발 전용 예시 어댑터로 분리했습니다. `#prepare/<requestId>`에는 공개 요청 식별자만 넣습니다. `Workspace`에는 현재 팀 이름을 전달하는 변경만 적용했습니다.

- `@noble/post-quantum`은 원본에 지정한 **0.7.1**로 고정했습니다. 전이 의존성 `@noble/ciphers / curves / hashes`는 2.4.0이며 모두 MIT 라이선스입니다. npm 무결성 값은 `package-lock.json`에 기록했습니다.
- 브라우저 검증용 `@playwright/test`는 **1.65.0**으로 고정했습니다.
- 기존 Vite 7.3.6의 알려진 취약점이 발견되어 기존 허용 범위 안의 **7.3.7**로 잠금파일을 갱신했습니다. 갱신 후 npm 감사 결과는 취약점 0건입니다. 이는 보안 감사 통과를 의미하지 않습니다.
- 의존성 검토는 패키지 명세·라이선스·잠금파일 무결성·npm 감사 범위입니다. 원본 소스의 독립 보안 감사나 브라우저/OpenSSL 상호 운용 검증을 대신하지 않습니다.

## 시험

2026-11-06 실행 결과: 일반 시험 **144개 통과**, 브라우저 시험 **43개 통과·2개 건너뜀**, 형식 검사·타입 검사·배포 빌드 통과입니다. 건너뛴 2개는 Firefox·WebKit의 실제 클립보드 시험입니다. 브라우저 기능 시험에서는 복사 대역을 사용했습니다. 배포 자바스크립트에서 개발 예시 저장소·조작기·후보 코드가 제외되는 것도 확인했습니다.

```bash
npm test
npm run format:check
npm run build
npx playwright install chromium firefox webkit
npm run test:browser
```

일반 시험은 상태 결합, 코드 5회 실패, 후보 바꿔치기, 승인 기한, 명시적 문맥 선택, 계획 해시·대상·연결 변경, 결과 불명·부분 실패, 키 재접속, 정리 미확인, 비밀 미저장, 명령 주입 거절을 포함합니다.

브라우저 시험은 공통 연결 흐름, 복사 거부·취소, 잘못된 코드, 계획 동의, 새로고침 복원, 클라우드 선택, 연결 해제, 결과 불명, 390·768·1024·1600px 배치, 실제 화면의 발급 차단을 검증합니다. Chromium에서는 실제 클립보드의 한 번 클릭 쓰기를 별도로 확인합니다. Firefox·WebKit 기능 시험은 제어 가능한 복사 대역을 사용하며 실제 클립보드 시험은 건너뜁니다. Playwright의 WebKit 시험을 실제 Safari 출시 검증으로 표시하지 않습니다.

실행 결과와 남은 범위는 PR 본문에 기록합니다. 실제 서버 기능, 지원 브라우저 출시 표, 고객 계정·클러스터의 실환경 연결은 후속 통합 작업입니다.

## 후속 서버 연결 조건

신규 `/v1` 경로의 로그인 쿠키·출처 검사·프록시, 서버 기능/권한, 상태·계획·작업 조회, 미사용 요청 취소, 이벤트 순서·재접속, 중복 방지·응답 유실 복구 계약을 확정해야 합니다. 확정 후 `unavailableConnections`를 실제 어댑터로 교체하고 실제 등록 자격·승인·터널 증거로 인수 시험을 진행합니다.

용어: API는 시스템 간 호출 규약, FE는 브라우저 화면 구현, PR은 GitHub 변경 검토 요청입니다. 복사 대역은 실제 클립보드 대신 성공·실패를 제어하는 시험용 구현입니다. 그 밖의 용어는 [계획서의 용어 풀이](INFRASTRUCTURE-CONNECTION-FRONTEND-PLAN.md#용어)를 참고하세요.
