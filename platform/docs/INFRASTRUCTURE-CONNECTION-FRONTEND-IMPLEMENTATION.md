# 환경 연결 화면 구현 및 로컬 확인

작성일: 2026-11-06
대상: PR #14, `feat/platform-prepare`

## 현재 화면 결정

사용자의 후속 요청에 따라 새 환경 연결은 **1. 환경정보 수집 → 2. 환경등록** 두 단계만 제공합니다. 초기 여섯 단계 화면 계획보다 이 결정을 우선합니다.

| 단계 | 제공하는 행동 |
| --- | --- |
| 1. 환경정보 수집 | 명령 복사·실행, 웹에서 단말 코드 확인, 보안 연결, 단말에서 찾은 계정·Kubernetes 문맥 확인과 선택한 대상의 자원 설정 조회 |
| 2. 환경등록 | 수집된 계정·클러스터 정보 확인, 프로젝트·환경 이름·출발/도착 역할 입력, 수집 결과에 결합한 환경등록 |
| 이후 앱 선택 | 마이그레이션 범위, 데이터·비밀 읽기·복호화 권한, 설치·변경·실행 계획을 검토할 예정이며 **아직 미구현** |

명령 실행·단말 확인·보안 연결은 첫 단계 안의 진행 상태이며 별도 상단 단계로 세지 않습니다. 최초 진입 시 환경 이름·종류·역할을 입력받지 않습니다. 조직은 로그인 문맥에서 결정하며 미리보기에서는 로컬 예시 조직을 사용합니다.

환경 종류·계정·리전·클러스터 신원은 수집 결과를 사용합니다. 등록 화면에서 확인한 실제 대상을 다른 종류로 바꿔 입력할 수 없습니다. Kubernetes 문맥은 읽기 조사 전에 사용자가 명시적으로 선택합니다.

환경등록은 확인된 정보에 이름과 역할을 저장하는 행동입니다. 설치나 고객 권한 변경·데이터 이관을 수행하거나 승인하지 않습니다. 이관 작업의 권한·계획 승인 보호를 제거한 것이 아니라 그 검토 위치를 이후 앱 선택 범위로 구분한 것입니다.

## 실제 연동과 미리보기의 경계

**구현한 것은 브라우저 화면과 개발 전용 상호작용입니다. 새 단말 등록·터널·환경정보 수집·환경등록 서버는 아직 연결되지 않았습니다.**

기존 애플리케이션 백엔드는 로컬에서 별도로 실행할 수 있으며 로그인·회원가입·팀 관리는 로컬 데이터베이스를 사용합니다. 기존 개요·환경·보안의 서버 시뮬레이션 자료와 이 개발 전용 환경 연결 예시는 별도입니다.

| 주소 | 동작 |
| --- | --- |
| `/#prepare` | 실제 로그인 앱의 준비 화면입니다. 새 연결 서비스 준비 중 사유를 표시하고 실제 수집 명령 발급을 막습니다. |
| `?connection-preview=1#prepare` | 개발 서버에서만 전체 수집·등록 흐름을 재현합니다. 실제 고객 자원에 접속하지 않습니다. |
| 배포 빌드 | 개발 미리보기 진입점·상태 조작기·예시 자료를 포함하지 않습니다. |

## 로컬 실행과 확인 순서

```bash
cd ~/workspace/competition/2026-softbank/1_main/dev/platform/frontend
npm ci
npm run dev:connections
```

이미 4320 포트에 개발 서버가 실행 중이면 [로컬 미리보기](http://127.0.0.1:4320/?connection-preview=1#prepare)를 여세요.

1. 처음 화면에서 **환경정보 수집** 단계와 단말 준비 안내를 확인합니다. 프로젝트·환경 이름·역할 입력은 아직 보이지 않습니다.
2. 준비 체크 후 `미리보기 명령 복사`를 누릅니다. 클립보드에는 실행 불가능한 설명 주석만 들어갑니다.
3. 아래 `단말 실행 재현`을 누르고 코드 `ABCD 2345`와 확인 체크박스로 단말을 승인합니다. 이 동작들은 모두 첫 단계 안에 있습니다.
4. `터널 확인 재현`을 누릅니다. 단말에서 찾은 예시 계정이나 Kubernetes 문맥을 직접 선택하고 `선택한 환경정보 수집`을 누릅니다.
5. **환경등록** 단계에서 수집된 환경 종류·신원·자원 정보를 확인하고, 프로젝트·환경 이름·역할을 입력한 뒤 `환경 등록`을 누릅니다.
6. 등록 완료 정보를 확인합니다. `다음: 앱 선택`은 아직 미구현이므로 비활성입니다.
7. `다른 상태 살펴보기`에서 단말 확인 대기·수집 완료·등록 완료·명령 만료·연결 장애·키 교체·해제 후 정리 미확인을 바로 열 수 있습니다.

미리보기 데이터 형식은 수집·등록 분리에 맞춰 세션 저장소 `oneport.connection-preview.v2`로 바꿨습니다. 이전 여섯 단계 미리보기 상태는 이어서 복원하지 않습니다. 이전 요청 주소가 남아 있으면 `새 환경정보 수집`을 누르세요. 기존 일반 앱의 로그인 계정·데이터베이스 자료는 변경하지 않습니다.

현재 화면 캡처: [환경정보 수집](assets/connection-frontend/environment-collection.png), [환경등록](assets/connection-frontend/environment-registration.png), [모바일 환경등록](assets/connection-frontend/environment-registration-mobile.png). 모두 실제 고객 자원이 없는 개발 미리보기입니다.

## 유지한 보호 조건

- 브라우저는 복사 클릭 때만 등록용 키를 만들고 공개키만 전달하는 구조를 유지합니다. 등록 생성값·개인키는 화면·주소·세션 저장소에 넣지 않습니다. 미리보기 클립보드에는 비밀도 실제 실행 명령도 넣지 않습니다.
- `@noble/post-quantum@0.7.1`은 잠금파일에 고정합니다. 브라우저 생성값으로 공개키를 재현하는 시험은 수행하지만 브라우저/OpenSSL 교차 검증이나 실환경 보안 시험으로 표현하지 않습니다.
- 단말 등록 증명 접수 60초와 웹 확인 최대 5분은 별도입니다. 코드 최대 5회·후보 해시·조직·권한 확인도 유지합니다.
- 등록 버튼은 승인된 단말·준비된 터널·수집 완료·수집 자료 해시·현재 등록 권한이 있어야 사용할 수 있습니다. 수집 중 폐기·키 세대 변경이 발생하면 늦은 결과를 등록 가능한 자료로 채택하지 않습니다.
- 수집된 대상·조직·종류·리전·자료 해시가 바뀌면 등록을 거부합니다. 이미 등록한 요청을 다시 등록하지 않습니다.
- 키 교체·재접속은 환경등록 정보와 독립적으로 처리합니다. 연결 해제 시 서버 차단·터널 차단·고객 권한 정리·단말 정리의 확인 여부를 구분합니다.
- 데이터·비밀 값 읽기·복호화·이관 생성/수정 권한과 설치 계획을 정보 수집이나 환경등록에 포함하지 않습니다.

## 검증

```bash
npm test
npm run format:check
npm run build
npm run test:browser
```

현재 일반 시험 **147개 통과**, Chromium·Firefox·WebKit 브라우저 시험 **34개 통과·2개 건너뜀**입니다. 건너뛴 항목은 Firefox·WebKit의 실제 클립보드 시험이며 기능 시험에는 복사 대역을 사용했습니다. WebKit 시험을 실제 Safari 출시 검증으로 표현하지 않습니다.

브라우저에서 상단 두 단계, 수집 전 입력 부재, 단말 코드 실패, 명시적 대상 선택, 수집 후 등록 입력, 등록 결과·새로고침, 클라우드 종류 자동 반영, 명령 기한 종료, 해제 후 정리 미확인과 390·768·1024·1600px 배치를 확인했습니다.

## 후속 서버 협업

수집 요청을 조직·현재 사용자 권한에 결합하는 계약과 읽기 대상 확인·조회 권한, 환경정보 조회·불변 자료 해시·환경등록 저장 계약이 필요합니다. `ConnectionGateway`는 화면용 제안 계약입니다. 없는 운영 경로를 추측해 호출하거나 기존 전달 토큰 등록 스크립트를 사용하지 않습니다.

신규 `/v1` 경로의 로그인 전달·출처 검사·프록시, 미사용 요청 취소·상태 조회·이벤트 복구·중복 방지 계약도 선행 과제로 유지합니다. 실제 서버가 구현된 뒤 소속·권한·수집 대상·등록 결과에 대한 인수 시험이 필요합니다.

용어: API는 시스템 간 호출 규약, PR은 GitHub 변경 검토 요청입니다. 복사 대역은 실제 클립보드 대신 성공·실패를 제어하는 시험용 구현입니다. 기존 설계 및 추가 용어는 [초기 계획과 후속 결정 기록](INFRASTRUCTURE-CONNECTION-FRONTEND-PLAN.md)을 참고하세요.
